# Reliable Text-to-SQL Data QA Assistant

Ask a question about medical-device companies' financial statements in plain English and get an answer computed from SEC filings, together with the SQL that produced it. The assistant refuses questions the data cannot answer, and generated SQL passes three safety layers before it touches the database.

## Problem
Companies have too many tables, so SQL generated by LLMs is often inaccurate.
V1 tackles this on a bounded 3-table slice and measures accuracy with a fixed evaluation set.

## User
Junior industry/equity analysts who can't write SQL but need numbers like "Dexcom's revenue last quarter" without opening filing PDFs.

## How it works
```
question
  → ask(): Claude (claude-haiku-5-5) + schema doc + glossary → SQL or CANNOT_ANSWER
  → validate(): single SELECT only, no data-changing statements, table whitelist, auto LIMIT
  → run_sql(): read-only role `text2sql_reader`, read-only transaction, 5 s timeout
  → on SQL error: send the error back to Claude, retry up to 2 times
  → respond(): table + SQL + source; empty result is reported as missing data, never as 0
```

Example:
```
$ python src/app.py "What was Dexcom's revenue in Q3 2025?"
value
1209300000.0000
SQL: SELECT ff.value FROM companies AS c JOIN filings AS f ... WHERE c.name ILIKE '%dexcom%' AND f.fy = 2025 AND f.fp = 'Q3' ...
Source: SEC Financial Statement Data Sets, 2025Q4 (20 medical-device companies).
```

## Safety: three layers
| Layer | What it does | Evidence |
|---|---|---|
| 1. Prompt | Return `CANNOT_ANSWER` for questions outside the data (stock prices, forecasts, filing text, market share) | Refusal cases q06/q09/q10 and attack cases q11–q13 were all stopped here |
| 2. `validate()` (sqlglot) | Parse SQL; allow exactly one SELECT/WITH/UNION statement; reject INSERT/UPDATE/DELETE/DROP/CREATE anywhere in the tree; whitelist tables (+ CTE names); block dangerous functions (`pg_sleep`, `pg_read_file`, ...); add `LIMIT 1000` if missing | `pytest` suite in `tests/test_validate.py`: 3 safe queries pass, 14 attacks are blocked (CTE with `DELETE`, stacked statements, `COPY`, comments, mixed case, `pg_catalog`, settings functions). Writing these tests found two gaps, now fixed: other schemas (`other_schema.companies`) and `current_setting` / `set_config`. The validator has not yet been triggered in the eval, because layer 1 caught every attack first |
| 3. Database | Role `text2sql_reader` has only `SELECT` on the 3 tables; read-only transaction; 5 s statement timeout | `DELETE` and `pg_shadow` access return `permission denied` |

## Evaluation
Execution accuracy on a fixed set of 13 questions, each run 3 times because LLM output is nondeterministic:
- q01–q05, q07, q08: answerable (single value, ranking, YoY growth, ratio, filters). Graded against hand-written gold SQL; numbers match within 0.1%; ranking questions are checked in order.
- q06, q09, q10: must refuse (stock price, CEO name, market share).
- q11–q13: attacks (delete rows, prompt injection with `DROP TABLE`, read `pg_shadow`). Pass = refused or blocked; attack SQL is never executed.

Final result (2026-11-01, 3 runs): **39/39**. This means the two known flaky patterns did not recur on this set; it is not a claim of 100% accuracy in general.

How accuracy improved (each fix came from a diagnosed failure):

| Version | Change | Result |
|---|---|---|
| baseline | schema doc + glossary | q06 failed: answered a stock-price question with SQL |
| + refusal rule | `CANNOT_ANSWER` rule in prompt | 10/10 single run |
| + multi-run eval | run every question 3–5 times | exposed flaky q03/q04/q07: 29/30, then 48/50 over 5 runs |
| + schema v0.3 | add column types (`ddate` is DATE, not yyyymmdd int) | fixed `ddate - 10000` bug → 49/50 |
| + glossary rule | filter `ddate` to exclude prior-period comparative rows | fixed row-count mismatch → 50/50 (5 runs) |

Failure taxonomy found along the way: missing data, schema doc lacking types, brittle grader, SQL execution error, domain gap (fiscal year, comparative rows), no refusal, nondeterminism.

## Run it
Requirements: Python 3.12, PostgreSQL, an Anthropic API key.
```bash
python -m venv .venv && source .venv/bin/activate
pip install anthropic python-dotenv psycopg pandas sqlglot
echo "ANTHROPIC_API_KEY=..." > .env
createdb sec_fsds && psql -d sec_fsds -f sql/create_tables.sql
python src/load_data.py          # expects data/raw/2025q4/{sub,num}.txt and data/raw/company_tickers.json
python src/app.py "What was Dexcom's revenue in Q3 2025?"
python src/evaluate.py
```
Create the read-only role once (see the Safety section): `CREATE ROLE text2sql_reader LOGIN;` then grant `CONNECT`, `USAGE ON SCHEMA public`, and `SELECT` on `companies`, `filings`, `financial_facts`.

## Limitations (V1)
- One quarterly package (2025Q4): no quarter-over-quarter or multi-year trends. Only one company (Becton Dickinson, Sept fiscal year end) has a 10-K in this package; the rest have 10-Qs (e.g. Dexcom's FY2025 10-K is filed in 2026), so "fiscal year 2025" questions often correctly return no data.
- 13 eval questions is small; results show the method works, not general accuracy.
- Only one model (Haiku) tested so far.

## Next (V1.1)

## V1 does NOT include
- Multiple databases, microservices, Redis/RabbitMQ, self-hosted GPU inference
- Fine-tuning, multi-agent orchestration, a large frontend
- Any proprietary or employer data: public SEC data only
